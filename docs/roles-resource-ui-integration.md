# Normal resource forms and project-task permissions

This local draft extends the existing Company Roles continuation. It changes no live account, permission, tenant setting or provider configuration. Server authorization and the finite resource adapters remain the authority; operation names below are route identifiers, rather than editable grants.

The normal save adapter now recognizes the five existing manual template signatures, catalog creation/application, subcontractor creation/profile/compliance/archive, and both existing project-contract methods. Actual template default uses `POST /api/daily-templates/default` with a `templateId`; project binding uses `PATCH /api/projects/:id/template`. Template item routes accept only canonical numeric IDs or the protected `standard` template. Project contract changes contain only `contractValue`; project date changes contain only `startDate` and/or `endDate`. Mixed date/pricing payloads stop before a preview.

Linked project tasks use the same reason, server preview, unchecked explicit confirmation, technical original identity and original-outcome recovery flow for create, edit, removal, date changes and assignment. The server supplies current projected tasks and preserves the existing linked-task scheduling engine, dependency cascade, status choices and assignment behavior. Current scheduling create/edit/remove actions govern the corresponding controls. PM controls additionally retain stored `scheduleCrews`, assigned project and assigned crew boundaries. These checks add no capability that could broaden Assistant eligibility or fixed Owner/Admin management.

The preview renders complete nested template fields, answer options, conditional questions, completion requirements, assignment metadata, task consequences and subcontractor consequences as readable text. Server-supplied values enter text nodes. Editing a template preserves existing field IDs, conditional rules, assignment metadata and review notices instead of silently discarding them.

After an acknowledged selected-workspace save, normal handlers use the adapter's fresh reload. They do not append or merge an acknowledgment into template pins, catalogs, project estimates/contracts, subcontractors or private task caches. Older nonselected behavior remains intact. Task response sequences, edit drafts, unassigned-lane caches and task touch controllers retire together with workspace resource views; a held earlier response cannot paint its old pane. A fresh authorized project view is reopened after a task save.

`resource-browser-extended.test.js` owns an isolated memory fixture and private desktop/mobile browser context. It blocks every external request and uses only synthetic credentials/data. It covers normal nested template creation/versioning/default/binding/removal, catalog creation/application, contract PATCH, subcontractor creation/profile/archive, linked-task create/edit/status/dates/removal/assignment, restrictive PM controls and held task response retirement. Existing contract PUT and compliance-only PATCH lack distinct current forms, so those two signatures are exercised through the actual application adapter with the same visible review dialog. The test records source hashes, head, working diff, requests, screenshots and any explicitly pending checks; it is not a production or exact-CI acceptance claim.

The broader Roles release still requires integrated server tests, frozen-head verification, independent acceptance and separately authorized exact CI/upload. No merge, deployment or production policy change is included.
