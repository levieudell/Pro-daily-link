STATUS
The dataset is validated against the actual PDL application APIs in an isolated local test. It is not installed in a live tenant. SECURE LIVE ACCESS PATH
1. First verify whether the owner already has authorized ordinary access to a separately owned demo workspace. Do not reset Northstar, Sample Builders or an internal test account without verifying their purpose and ownership.
2. If none exists, the owner creates a separate company named exactly DEMO | Alder Ridge Builders using normal signup and enters their own password. The owner must accept the applicable linked terms. No credentials are included here.
3. After the exact tenant ID and empty state are verified, an authorized platform-owner operation must install the fixture inside normal tenant concurrency, persistence and backup controls. The included preparation function rejects nonempty tenants, billing links, multiple users, ID mismatch, or an already seeded fixture. It performs no write by itself. The guarded Prepare sales demo button is included in the reviewed initializer release; it becomes available only after that release is deployed.
4. Keep the tenant marked demo=true, billingExempt=true, planPrice=0, with no Stripe customer or subscription link. Preserve the owner's existing login. Do not copy owner credentials to another account or manufacture support access.
5. Verify the live app with that owner, counts and totals against summary.json, then verify persistence after reload. Only then share its actual app URL as ready. Browser, live access and production persistence remain unverified by this package.

RECOVERY
A new empty demo tenant is preferred. Retain the pre-seed empty tenant snapshot using the product's authorized backup process, and apply only within the exact tenant's write queue. No live-state restore command is provided here because overwriting data needs verified target, ownership and recovery controls.
