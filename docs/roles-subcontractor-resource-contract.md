# Subcontractor resource contract

This slice adds four finite adapters to the existing resource preview, confirmation, revision, receipt and recovery mechanism. It does not add a permission dictionary, role flags, provider action, guest grant, deployment or production setting. Base: `ac1e3bc812cc8ecec3a8d1f060f33a069f2f5877`.

| Kind | Existing route | Effective existing baseline | Exact consequences |
| --- | --- | --- | --- |
| `subcontractorCreate` | `POST /api/subcontractors` | Current Owner/Admin | One generated ID, submitted bounded contact/compliance fields, Active state, null archive timestamp, first generated history entry. |
| `subcontractorProfile` | `PATCH /api/subcontractors/:id/profile` | Current Owner/Admin | Only named contact/compliance fields; existing tracked-field history semantics; reset reminder stages; cancel existing queued reminders for that subcontractor. |
| `subcontractorCompliance` | `PATCH /api/subcontractors/:id` | Current Owner/Admin | Only named compliance fields and notes; existing compliance-signature history semantics; reset reminder stages; cancel existing queued reminders for that subcontractor. |
| `subcontractorArchive` | `PATCH /api/subcontractors/:id/archive` | Current Owner/Admin | Archive or restore with generated history; archive revokes only the subcontractor's currently Active project links; cancel existing queued reminders for that subcontractor. Restore retains revoked links. |

The effective baseline comes from the early guard in `server.js` for all four route booleans. The later compliance handler also mentions PM, but the earlier Owner/Admin guard already rejects PM. This adapter preserves that boundary, including for a PM assigned to the subcontractor's projects. Existing PM directory visibility is not converted into mutation authority.

Inputs use closed operation and detail objects. They exclude IDs, tenant IDs, project grants, guest tokens, reminder stages/history, account roles and provider state. Name/contact/email/phone/license/notes limits match the named legacy handlers. Email is normalized; phone requires seven to fifteen digits. Expiration dates are real ISO calendar dates or the explicit empty value. Compliance booleans and archive/restore are explicit booleans. Create accepts the normal form's `status: 'Active'` only and generates all history/archive fields on the server. Duplicate active company names, foreign tenant rows, duplicate canonical subcontractor IDs and orphan or foreign guest links fail before mutation.

The adapter runs the actual named legacy handler on the candidate and validates its entire resulting business snapshot. It verifies precise target fields, generated history actions/details/actors/timestamps, unchanged pre-existing history, target-only guest link revocation, unchanged guest secrets and unchanged unrelated accounts, projects, reports and other collections. Retained receipt evidence includes the complete old subcontractor, archive links, and affected prior reminder jobs; it stays private under the existing signed custody mechanism.

`prepareCandidate(before, after, op, auth, h, input)` calls the specific pure cancellation helper after the named handler and before `validate`. Root integration supplies `h.validateCompliance(db)` and `h.cancelCompliance(db, subcontractorId)` through `createCompliance`. The latter uses that module's existing private proof signer and validator, changing only a matching `queued` status to `cancelled`. Validation requires identical job ordering, count, source, identity, timestamps and other fields; only the matching queued job's status and correctly signed proof may change. `sending` and `uncertain` outcomes block the three existing-target writers. Completed `sent`, `rejected` and `cancelled` records remain byte-for-byte, including accepted provider evidence. No preview or confirmation stages, dispatches, retries or sends a reminder. An existing ledger without the reviewed helper contract fails closed.

Fresh confirmation and replay projection uses the current authorized bootstrap subcontractor DTO. It excludes private tax/source data, history, stages and guest tokens and never returns the cached receipt body. If current visibility contains no record, the result is a technical ID/receipt acknowledgment. Shared admission must continue to reauthenticate after awaits, enforce revision/source/session/role freshness, capture the signed receipt and enforce commit deadlines. Shared normal UI must reload current records after acknowledgment, avoid replacing fresh caches with old form or receipt values, and keep history private rather than inventing missing entries. Archive preview should state that active guest links will be revoked and existing queued reminders canceled.

`node resource-subcontractors.test.js` passes 21 grouped checks. Its harness extracts the four actual named handlers and early guard from the checked-out `server.js` and runs those source blocks against synthetic snapshots, with external calls unavailable. It exercises all four handlers, effective PM/field/platform denial, malformed inputs, tenant and identity failures, duplicate names, exact compound effects, malicious collateral mutations, signed queued cancellation, uncertain-provider denial, completed-job evidence retention, legacy string-ID behavior and fresh DTO projection. It uses the actual compliance delivery proof validator; the cancellation test hook signs only synthetic job transitions with a fixture key. It does not claim full HTTP, browser, PostgreSQL, stale-session or commit-deadline acceptance. Root integration adds this suite to the exact CI commands and supplies those shared admission checks.

The legacy compliance handler uses a strict numeric ID lookup; profile and archive canonicalize numeric/string IDs. The adapter preserves that actual difference: a canonical legacy string ID supports profile/archive but receives the existing 404 for the compliance-only route. No existing record ID is rewritten.
