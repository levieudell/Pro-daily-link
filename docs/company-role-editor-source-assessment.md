# Company Settings Roles integration: source draft

This draft adds an Owner-only Roles tab to the existing Company Settings page on the isolated compatibility adapter. It edits the six existing typed families: scheduling, private time off, time review, time cards/pay periods, dailies/workdays, and project notes/to-dos (32 actions). No production configuration, grant, account, key, database, merge, deployment or activation is authorized or performed.

The existing framework supplies Owner, Admin (including legacy Office normalization), Project Manager, Foreman and Field ceilings, stored grants, project/crew/member scope, feature/account locks and pricing restrictions. A crew name is assignment scope rather than an additional account role. Missing policy retains the exact inherited defaults. Saved role limits and named profiles intersect those existing ceilings; they cannot grant broader scope or financial access.

Owner, tenant/security/account management, billing, pricing boundaries and fixed Assistant eligibility stay outside editable flags. Office is an optional protected Admin-base profile initially carrying eight read actions and no assignments. Custom profiles inherit one existing base role and its scope; assignment requires that same role. Owner/platform bindings, in-use retirement, reuse of retired IDs and invalid required models fail closed. Admin management/pricing authority remains inherited and is not represented as globally read-only Office access.

Every change has a server preview, affected-account and notes-project impact, reason, expected tenant revision, expiry, original Owner session binding, purpose-specific HMAC custody, explicit unchecked confirmation and immutable linked audit/receipt. Preview does not apply permissions. First confirmation uses fresh authority and guarded compare-and-swap; replay uses the exact original envelope and cannot overwrite a later policy. The client accepts a changed authority only on the named policy-confirm route with a current Owner and a server-validated before/after authority link. Other routes, actors or substituted headers do not bypass response retirement.

Unknown acknowledgements retain only technical request identity in the original tab. Reload performs no automatic resend. A new session cannot adopt the original proof. Explicit review of current state/activity can retire the browser's unknown marker while retaining its unknown history. Marker storage failure prevents the first confirmation POST. Navigation, revocation and stale responses retire private editor DOM; cached confirmation is cleared on blur/visibility changes. Neither browser storage nor cached preview flags authorize a server action.

The repository and independent synthetic platform sink verify and lock the exact deferred deadline-trigger contract through actual COMMIT. Installation is restricted to explicit loopback test fixtures; no numbered production migration or startup activation hook was added. Native regressions cover malformed/absent/disabled/conditional/wrong-event triggers, pre-lock replacement, blocked disablement, natural expiry and held actual COMMIT rollback.

The editor API and browser tests are additive to the unfiltered application suite and native workflow. Browser tests use real credential login, normal Company Settings controls, desktop/mobile viewports, explicit synthetic fixtures and zero allowed external requests. Native role tests cover original-session rejection/revocation, competing Owners, altered custody, Office assignment, commit acknowledgement loss/restart/replay and a later policy invalidating the old receipt. Exact-head execution evidence and independent review must accompany this draft; source availability alone is not release approval.

This completes the bounded editor implementation prerequisite, not the entire release. G3 resource lifecycle/settings writers remain open, as do G4 broader report variants, G5 financial/commercial flows, G6 physical files, G7 global/platform/provider topology, G8 complete Assistant integration, G9 durable retention/backup and G10 writer-fence/restore/release proof. The current policy history bounds (1000 previews/1000 receipts/2000 audit entries/8 MiB) and tab metadata limit (16 retained entries) fail closed without pruning; durable indexed retention remains G9 work. Unsupported routes retain their explicit synthetic admission denial. No full release or production activation is claimed.
