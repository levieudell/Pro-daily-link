## Actual code milestone

Existing forgot-password/reset-password/login/app pages and existing API paths now have a **quarantined synthetic integration** with selected-tenant revision/CAS storage. There is no alternate workspace. Normal startup cannot activate this slice: only an explicit in-process test install, `NODE_ENV=test`, strict auth, a synthetic marker and loopback origins/storage are accepted. Unknown selected private paths stop before legacy routing. This quarantine is test infrastructure, not a usable app mode or a workflow-preserving release.

The implemented vertical journey is request reset → committed encrypted delivery → guarded synthetic send → existing reset page → atomic password/token/session change → old-session denial → ordinary sign-in/me/state. Native-backed desktop/mobile checks reach the existing workspace/profile. They also report incomplete normal workflow calls honestly; reaching the profile is not proof the entire dashboard works.

- `account-credential-delivery.js` implements one purpose, password reset. Token/hash/generation, 30-minute expiry, recipient/origin and AES-GCM custody commit together. AAD binds immutable job ID/key version and account/purpose/generation. Canonical job and account identity validation rejects duplicate/poisoned records even with a recomputed snapshot hash.
- A guarded committed send admission defines external-delivery ordering. Revocation first prevents admission; admission first can finish delivery later, but revoked/rotated/consumed credentials cannot be used. A sending/uncertain job is never reassigned on lease expiry. Provider outcomes are closed; errors/contradictions become uncertain without raw provider bodies/logs. Explicit subsequent forgot requests rotate to a new generation. No automatic retry/resend or real delivery adapter exists.
- `database/compat-tenant-repository.js` reuses the existing revision/record CAS function with consistent repeatable-read loads and shape-preserving empty collections. Expected revision and credential/session deadline are checked after the actual row lock. Rejected writes leave authority/mirrors untouched. Lost COMMIT acknowledgements produce a safe unknown outcome; there is no exact durable reset receipt replay. New-password sign-in is the tested current-result recovery.
- Current protected authority is assembled from the loaded tenant/session before each action and again before protected response delivery. Shared finite evidence rejects aliased IDs, duplicate session hashes, foreign tenant sessions and nested role/name/grant values before legacy authentication; it does not normalize ambiguous legacy records into authority. The five existing PM grant names are the only accepted grant keys in this synthetic slice. Natural expiry and account locks are checked after the final load; account-access recovery data is recomputed there. Session renewal, state repairs and login/logout writes stage through CAS for the admitted slice; old disk feature flags/mirrors cannot replace its authority. Exact production directory shape compatibility remains unproven and cannot be inferred from these fictional fixtures.
- Private delivery/custody/hash/generation fields are omitted recursively from admitted responses. No new private collection is exposed through state. Unsupported user/export/provider routes are quarantined until their own projections and effects are integrated.
- Existing UI starts only after a successful strict workspace gate, and login credential intent waits for/suppresses stale resume navigation through response JSON completion. The byte-buffered body reader preserves split UTF-8 transport. Existing failed-auth buckets still count credential failures exactly once.
- Selected discovery is fixed configured metadata, not an email directory. Credential POSTs require the canonical tenant header. A valid public reset can proceed despite an unrelated ambient cookie, while protected workspace reads cannot. Signup page navigation uses the configured separate legacy global origin; actual founder/signup/new-company/me remain on the ordinary service.

The policy/profile editor and effective32-action restrictions are **not installed** by this slice. Owner/security/billing/pricing/export ceilings, old stored defaults/scopes and fixed Forged-only PM/Admin/Owner Assistant eligibility remain immutable. This source milestone cannot change what a production role can do.

## Validation and stopping criteria

New ordinary tests cover plaintext absence, header/Origin/cookie admission, malicious payloads, duplicate/aliased identity, canonical/poisoned jobs, same-generation duplicate sends, known/unknown/contradictory provider outcomes, paused dispatch/revocation, expiry, token consumption, old/new session and password acceptance, current-response natural expiry, rate-limit counting, rejected and committed-but-lost acknowledgements, intact legacy JSON and explicit ticket-cleanup/unknown-writer stops. No live token/provider is used.

Native PostgreSQL tests use a separately named local synthetic database, source007/008 only there, denied anon/authenticated CAS grants, consistent empty/null/absent shapes, credential lifecycle/poisoned content, two independent repository processes competing with revocation and expiry after a real held row lock. This is not a full multiworker HTTP proof. Browser tests use isolated contexts/native storage, explicit fictional fixtures and separate loopback hosts, and block every external request. Eight cases cover desktop/mobile recovery, four actual app-script failed/non-true gates, actual login held-resume JSON and ordinary global signup/new-tenant me. Four PNGs and a JSON inventory are emitted. Existing Google Fonts may be attempted but are aborted; zero external requests are allowed. Provider environment variables are explicitly empty before either server import, including local-env loading.

Complete Linux Node20/22 ordinary suites plus a PostgreSQL16/native/browser workflow and independent exact-head review are required. A Windows local ordinary run hits the unchanged POSIX0600 backup-mode assertion (`438 != 384`) in `sales-demo-route.test.js`; this does not provide full-suite credit or justify changing that unrelated assertion. Exact Linux results must decide validation.

Stop before offering a mode that drops normal workflows, performs an unguarded precommit effect, restores old snapshots, exposes credential custody, enables unreviewed policy breadth or expands fixed authority. The code currently stops at the retention/remaining-writer boundaries, so it cannot activate. Remaining work is engineering/acceptance work, not another generic owner approval request. Any future production schema/cutover/routing/key/provider/activation or exact permission change requires its separate concrete action-time approval.

Whole release gates closed:0. G1-G10 remain open. This is a code/test milestone toward G1/G7, not full compatibility or production readiness.
