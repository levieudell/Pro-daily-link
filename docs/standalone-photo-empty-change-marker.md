# Standalone photo empty Change marker

The ordinary project-photo form emits changeId:null. Reviewed photoUpload intake accepts this exact empty compatibility marker, as well as an absent marker, and normalizes both to the same canonical unlinked operation. The marker is omitted from the preview/receipt/storage operation.

Every own non-null changeId is rejected before custody preparation, including numeric IDs, strings, zero, booleans, arrays and objects; unknown fields remain rejected. This does not admit Change attachments or add an editable permission. Existing current account/company/project, effective Daily permissions, report/workday linkage, byte custody, revision/confirmation/replay/revocation/deadline checks remain in force.

The regression exercises actual HTTP preview/confirm/read/replay/revoke flows. Malicious linkage attempts leave the complete synthetic snapshot, revision and custody unchanged. The full rollout browser uses the real ordinary photo form and all original assertions. No no-policy role defaults or normal legacy writer were changed.
