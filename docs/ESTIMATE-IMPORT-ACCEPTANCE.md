# Estimate import acceptance and fixture provenance

This change fixes embedded-text PDF row boundaries, missing units, rate-versus-amount selection and review safety. It does not certify arbitrary QuickBooks exports or model/OCR accuracy. It changes no provider model, SDK, pricing, credentials or deployment settings.

## Verified behavior

The local reader preserves positioned text rows instead of flattening headings into scope descriptions. It supports a limited literal-string Tj/TJ subset, not general PDF font/Unicode decoding or all multi-table positioning. Identified quantity/rate/amount columns are interpreted in validated order. A missing unit remains blank; hidden quantity remains null; missing or ambiguous amount remains null. Rate-only rows retain the printed rate separately. Cost/markup or contradictory Amount/Total headers are flagged instead of choosing the rightmost money value. Headerless legacy amounts remain review warnings. Rows labeled Not included are excluded; unlabelled visual greying requires assisted/manual review.

Recognizable rows with missing fields remain editable in office review. Quantity and unit must be confirmed before saving; missing selling amounts remain null in project items, not zero. A zero amount stays zero. Every confirmed row is validated before any row saves. Users can deselect scope rows; uncertain optional rows start deselected. Printed selling rates and internal costs appear separately. Internal cost is never substituted into selling amount. The legacy project item `cost` field stores the reviewed line amount; rate/internal-cost metadata remains on the source import draft.

Scans and readable PDFs with zero supported rows attempt assisted extraction only when the existing OpenAI configuration is available. Failure leaves a draft and warning, never approves automatically. Partial local extraction with omitted ambiguous rows does not automatically invoke AI; warnings require comparing the entire PDF. The authentic Smartsheet sample remains unsupported by the local reader and is an explicit assisted-review acceptance gap.

The assisted schema distinguishes nullable quantity, unit rate, selling amount, internal cost and explicit labor budget hours. Tax/discount/fee adjustments are separate document metadata and never construction scope. Group totals and components must not be double-counted. Document instructions are treated as untrusted content. Explicit hours survive review and catalog changes; unknown hours remain available for manual/catalog review. Sales prices, equipment hours, crew counts and durations never automatically become labor budgets.
