## Architecture and reused authority

The existing foreground dictation/command prototype remains available. A separate deterministic client controller adds guided spoken questions for missing fields in the explicitly selected project/action. It reuses authorized context, editable fields, the exact server preview, and the existing on-screen confirmation. It does not call AI automatically, interpret arbitrary tool commands, receive a save callback, persist conversation history, record audio, or send transcripts to a new provider. Project/action changes require the visible selector and restart; exact field changes invalidate the preview. Only a complete draft followed by the standalone `preview these changes` requests the existing read-only preview.

Supported actions remain single-day scheduling, the existing atomic multi-person/date/weekday batch, project notes and open unassigned to-dos. Guided batch bounds remain 31 calendar days / 10 people / 100 person-date pairs. One shift/task/instruction set applies to the whole batch. Duplicate names require an authorized person ID. Relative or ambiguous dates/hours are rejected; exact month/day/year or ISO dates and explicit AM/PM or HH:mm hours are accepted. Weekdays must be individually named; no implicit weekend selection. To-do conversation asks for no deadline, today in company timezone, or an exact date. No company timezone change is made through speech.

All answers are untrusted local draft values. Existing server routes retain fixed PM/Admin/Owner eligibility, fresh tenant/project/team authorization, leave/availability/DST/conflict/stale fingerprints, signed tokens, and durable idempotent confirmation/replay. The role overlay remains separate; its documented auth/me and state-reselection seams are unchanged. Server, assignment persistence, manual app screens, dependencies and existing AI transport are unchanged by this follow-up.

## Conservative speech lifecycle

Start is explicit. The assistant speaks one question with the microphone off, then listens for one final answer. It accepts at most 20 answers / 6,000 total transcript characters in five minutes, with a 30-second answer timeout. Interim, late, reported confidence below 0.75 (including zero), and multiple-final answers cannot advance a draft. Absent/unreported confidence remains untrusted draft input and still requires the exact preview and on-screen confirmation. Unknown commands or ambiguous `yes`, `save`, `confirm` and `do it` cannot save or request AI. Exact stop/cancel is honored even at low recognition confidence.

Prompt completion starts the next single answer only inside that explicitly started session. Unexpected browser end/error/denial, focus loss, hidden page, pagehide, context/role/company changes, manual editing, another speech mode, and cancel stop it; there is no error/end restart loop. Exact preview readback is complete, including every person/date, conflicts and notification policy; overlong readback is refused instead of truncated. Capture is off during readback. The final readback never resumes capture. Interruption during preview request or exact readback invalidates the guided preview; late replies are discarded and a fresh preview is required. Explicit on-screen Confirm is the only write trigger, including retries. It cannot save an interrupted guided preview.

This is guided foreground conversation, not a general real-time voice agent, background/locked-phone/wake-word/PSTN mode, or a driving workflow. Use only while stationary. Unsupported recognition or synthesis retains typed forms/preview/confirmation.

## Device/provider dependencies and cost boundary

Browser `SpeechRecognition` / `webkitSpeechRecognition` and `speechSynthesis` / `SpeechSynthesisUtterance` are runtime requirements. Recognition is not universally supported and may use a browser vendor's remote speech engine; audio may leave the device for that service. No offline/on-device processing guarantee is made. No language packs are installed and no permission is granted by this task. See [recognition documentation](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition) and [synthesis documentation](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis).

There is no new subscription, credential, grant, provider SDK, paid test, realtime connection or automatic Responses API request. The existing optional Suggest fields control retains its existing text/project-name/authorized-name disclosure and provider transport; guided voice does not invoke it. A future realtime or new speech provider would be a separate decision: first specify exact provider/model, audio/transcript/customer context scope, retention and a capped duration/spend/test choice. Existing key availability does not authorize paid testing or unbounded use.
