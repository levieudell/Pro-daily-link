# Bounded AI interpretation draft

Base: released main `cdea7221fe26b1fbd881288bef80f5f9680dd28c` (billing PR85, including PR87). Separate branch: `codex/project-assistant-ai-first-v1`. The billing trial markers, canceled-recovery logic, project caps and checkout-disable containment are preserved. Keep this feature separate from urgent releases. Default remains disabled; this draft does not deploy, merge, initialize production persistence or change any credentials, settings, schema, grants or subscription.

## Working vertical slice

Normal Send and finalized Talk transcripts can use the existing server-side OpenAI Responses connection to propose new project-scoped assignments with daily instructions. The exact example, “Schedule Chloe Andy at market Street tomorrow,” asks whether the user means Chloe and Andi, collects missing start/end/task/instructions one question at a time, then uses the existing conflict preview and explicit on-screen Confirm. Local name clarification, Back and field-clearing controls do not call the model. Existing notes/to-dos remain supported by the same bounded interpretation seam.

The feature supports existing owner/admin/project-manager access. It reuses company/project/crew restrictions and the assignment backend. Model output is untrusted: a strict field schema, literal-substring grounding, authorized name resolution and exact server-side date/time parsing apply before preview. Ambiguous names/projects/hours/dates require clarification. Relative dates are anchored to the company date when first supplied. A missing/invalid company timezone asks for owner confirmation through the established Company settings screen before any model request. Normal manual forms remain available.

Chat and preview make no assignment, note or to-do writes. Interpretation only writes private usage reservations/results. Existing authentication can renew its session separately. Preview shows exact names, IDs, dates, hours, timezone, task, instructions and conflicts. Confirm revalidates the actor, tenant, project, members, timezone, availability and signed preview fingerprint; existing durable confirmed receipts prevent duplicate assignment/in-app notifications. Scheduling emits no email. No voice command saves. No background commands or browser auto-start calls.

Cancel, Close, loss of focus, hidden page and workspace/role changes abort pending non-save HTTP requests and suppress late results. Server checkpoints before paid dispatch; cancellation after dispatch cannot promise to cancel provider billing. Confirm retains the existing uncertain-outcome retry path: retry the same confirmed preview, never construct a replacement save to resolve an unknown result.

## Authorized data boundary

Provider input contains only the current request, compact draft, last question, company-local date/timezone, and a bounded list of authorized display names. Before project selection it sends up to 20 project names; after selection it sends the selected project name and up to 20 permitted team member names. Server IDs, crew labels, stored reports/files, billing, customer contacts, unrelated projects, and secrets are excluded. The user’s own typed content necessarily forms part of the request. `store:false`; no model tools, SQL, autonomous execution, provider switching or new external subscription. A provider-neutral structured-intent adapter exists, with OpenAI as the only implementation.

Signed conversation states expire after 20 minutes and include the effective access digest. Duplicate paid-turn responses rebuild authorized context instead of replaying stale crew lists. Cached result content expires after 20 minutes; paid-turn receipt deduplication is retained for three days. Initial state-less UUID requests can run again after receipt/session retention ends; no permanent paid-call retry guarantee is claimed. Business-save idempotency uses the existing assignment receipt mechanism independently.

## Cost admission and limits

Approved limits apply only to this assistant interpreter: **$0.50 per company per UTC day and $5.00 across PDL per UTC day**, together in one durable private ledger. Other existing AI features are outside this feature ledger. Counts: one dispatched request per actor at a time, eight paid turns per 20-minute session, ten paid turns per user/hour and fifty per company/day. No automatic provider retries.

Only `gpt-5.4-mini` is admitted, using standard service tier, no reasoning effort, up to 1,400 output tokens and an 8,000-byte serialized payload. The documented prices are $0.75/million input and $4.50/million output tokens, with a 400,000-token context window. Source: [OpenAI model documentation](https://developers.openai.com/api/docs/models/gpt-5.4-mini). Structured-output behavior: [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Pricing allowlist expires at **2026-10-14 00:00 UTC**; after that, or with an unapproved `OPENAI_MODEL`, interpretation fails closed until reviewed pricing code is updated.

Before each dispatch, reserve the full documented input context window plus maximum output: **306,300 integer USD microdollars ($0.3063)**. This deliberately avoids relying on an unverified tokenizer/framing estimate. Successful responses settle once to measured token usage; a mocked 2,000-input/300-output call costs $0.00285, making the five-call example $0.01425 in that synthetic scenario. These are fixture calculations, not live provider measurements. Missing/invalid usage, timeout, refusal, malformed/ungrounded output, canceled uncertain requests or lost acknowledgements retain the full reservation. One uncertain call can therefore exhaust enough of the company allowance to prevent another admission that day. Any measured cost exceeding the reserved maximum closes future admissions. Do not erase/reset the ledger to regain allowance.

Each reservation performs a conditional PostgreSQL/PostgREST update on the existing private operations namespace’s `tenant_revisions` row. One compare-and-swap advances the revision and charges both company/global buckets. It preserves unrelated scalar data and tenant records and verifies the canonical snapshot hash. Multiple processes use the same ledger; no process-local spending fallback. The existing `SUPABASE_SECRET_KEY` remains server-only. Missing/corrupt/unavailable/overlarge accounting fails closed. Five-second storage timeouts and a 22-second turn deadline bound reads, reservations, provider and settlement handling. Ambiguous acknowledgements remain charged.

## Operator enablement preparation

No production step below was executed for this draft. Actual PostgreSQL/PostgREST capabilities remain unverified in this environment.

1. Release review must approve this separate feature and confirm current main after any urgent/billing release. Revalidate current approved model pricing and expiry.
2. With existing runtime credentials and feature still disabled, run `npm run assistant:ledger:check`. It is read-only, prints only readiness status and the existing operations namespace ID, and never dumps private records or keys.
3. If initialization is needed, review `database/assistant-budget-readiness.js` and its exact plan. `npm run assistant:ledger:initialize` is an explicit operator-only action: it appends an empty ledger to a valid existing private revision using CAS, or inserts the missing revision row for the already existing operations company with duplicate-ignore semantics. It never creates a company, changes SQL/grants, resets existing usage, or repairs corrupt storage. Re-run the read-only check after an uncertain acknowledgement.
4. Prove the existing service credential can read the consistent embedded snapshot and conditionally PATCH that private revision. An insert alone does not prove PATCH permission. Perform a controlled existing-ledger CAS check through the release process, preserving all data/counters; confirm two concurrent clients cannot both admit against the same revision. If schema, relationships, grants, RLS or service access are insufficient, prepare that exact change for owner review and **pause before executing it**. No migration or new access is included in this draft.
5. Confirm existing key/model settings, then separately approve `PDL_ASSISTANT_AI_ENABLED=1` through the normal release process. No new keys or permissions. Validate the mock-backed flow first; any live synthetic smoke would require separate authorization because this implementation task uses no paid AI tests. Validate supported real-device speech separately, including denial/unsupported fallback. Never use customer records for acceptance.

Recovery: set `PDL_ASSISTANT_AI_ENABLED=0` to stop new paid interpretation; manual screens and existing preview/Confirm remain available. Preserve the durable ledger, receipts and current reservations. Never reset usage, delete the namespace or replace its snapshot. Unknown save outcomes use the same confirmed token. Pricing/ledger/provider outages show manual fallback. For corruption or capability failures, keep the flag off and use the established private backup/recovery procedure.

## Evidence and capability limits

Synthetic API tests cover the example, literal grounding/minimum context, clarification/corrections, midnight anchoring, expired state, stale permissions/crew, injection, provider failure, unknown model, missing timezone, canceled-before-dispatch and duplicate confirmed saves. UI controller tests cover Cancel/Close/background/scope AbortSignals and uncertain-save retry. Headless desktop/mobile QA uses real application HTTP/auth routes with disposable fixtures, mocked OpenAI and mocked speech, blocked external browser routes, preview without business writes and explicit fixture-only Confirm. Shared-budget tests exercise 24 actual child processes against a synthetic HTTP CAS server, identical-turn/settlement races, both daily ceilings, hourly/session limits, lost acknowledgement and preserved unrelated private data. These do not prove live database privileges or physical speech support.

Boundaries: at most 31 calendar days, ten people and 100 person/day combinations through the existing batch backend; explicit weekdays. New assignments/instructions, notes and to-dos only. No existing-record edits, independent project dependency engine, project reporting agent, fleet/trucking functionality, hands-free real-time voice, phone/PSTN integration or background schedule execution. Browser speech may process audio remotely; the existing UI discloses this and offers typing/keyboard dictation when unsupported. Actual recognition and model interpretation quality require later separately approved acceptance. This first version can fail closed under the conservative spending reservation during outages.
