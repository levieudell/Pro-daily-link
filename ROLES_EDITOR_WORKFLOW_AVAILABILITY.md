## Four finite boundaries

- Photo submission uses named standalone `photoUpload` or compound `reportPhotoCreate`/`reportPhotoEdit` operations on existing routes. Strict bytes are retained privately at preview; metadata and receipts commit only after confirmation. Existing daily and safety handlers validate on one clone with staged photos, including photo-required templates, before one tenant commit. Creation does not require edit permission. The actual UI continuation consumes committed photos once, then refreshes. Stable project IDs determine scoped browser indexes.
- Protected delivery admits only named existing file GET routes. Current original project authority and typed daily visibility still apply. New files require signed byte custody and signed committed metadata bindings. Only an exact signed report-removal transition may detach a photo. Already committed custody cannot be reused for another upload. Older physical files require an explicit storage-read adapter; tests provide a fake adapter. Bounded private/no-store buffers leave the runtime only after final current-source/session checks.
- Existing office plan upload and pricing-authorized PDF intake use MIME/magic/canonical-base64/file/aggregate bounds. Embedded text reuses the existing parser. Optional OCR runs only through an explicit fake adapter, once at preparation with fresh pre/post authority checks. Parsed drafts retain only named fields. Estimate approval remains separate. Field/Foreman PDF scope proposals retain project scope without prices or automatic approval. Only the originating field actor can reopen that submitted PDF; unrelated field actors cannot gain its pricing-bearing bytes.
- Existing Assistant context/interpret and project context/chat/preview/confirm routes use fresh tenant sessions and current typed permissions. Fixed pilot roles exclude Field/Foreman/platform. Scheduling also requires stored scheduleCrews and PM project/crew scope. Notes/to-dos preserve visibility and send no notifications/public sharing. Signed custody binds original session, role, revision, authority, project and expiry; whole manual effects and receipts commit together. Reviewed provider-name redaction stays intact; conversational behavior is unchanged.

Every write uses server preview, initially unchecked explicit confirmation, revision/session validation, audit and exact original-result recovery. No arbitrary route can be opened by a role flag. Raw bytes, proofs, Assistant receipts and provider accounting stay out of state and Company JSON export. Review dialogs show names/types/details rather than base64 or private asset IDs.
